# Test strategy

The [Playwright configuration](../../playwright.config.ts) has four disjoint execution projects: API (`api`), desktop UI (`ui`), end-to-end workflows (`e2e`), and iPhone 13 Chromium emulation (`mobile`, reported as Responsive). One worker, zero retries; assertions default to 30 seconds. Mobile runs auth accessibility plus a task/profile workflow with horizontal-overflow verification. Auth is an overlapping functional subset of these projects, never an additional category in totals. Existing `npm test` remains Vitest.

API checks exercise 12 application-owned GET endpoints, unsupported methods and malformed inputs, role-dependent export, real Better Auth sessions/password/reset/origin boundaries, inventory grants, and file bytes/security headers/organization isolation. Framework auth paths and disabled feature behavior are distinguished in [API_ENDPOINT_INVENTORY.md](API_ENDPOINT_INVENTORY.md). Desktop UI checks cover anonymous redirects and authenticated dashboard/report rendering. E2E specs exercise contact CSV/edit/requirements/pipeline, developments, properties/inventory/access, billing/payments, documents/templates, tasks/calendar/account, marketing templates/campaigns/manual automation, and user/role/document administration. These are selected workflows, not full coverage of every operation or role.

Identity fixtures create a new organization, user, role/default grants and credential account for each test. Scenarios add only their own records. Tests prefer semantic locators; scoped CSS selectors document existing unlabelled file/select controls. Persisted data and selected audit records are checked through the dedicated database, and reload/relogin assertions distinguish persistence from transient UI feedback. Browser-based actions remain real application behavior; direct SQL is fixture setup or independent verification, not a substitute for the interaction being tested.

The launcher builds and starts Next in production mode on loopback port 3100 against the explicitly approved test database, using isolated `.next-test` output and a 360-second readiness budget. This avoids development HMR reloads interrupting workflows. Real production Secure cookie/CSP/trusted-origin policy remains active on the local loopback target; these runs do not verify deployed TLS/proxy configuration. Production Better Auth rate limits also apply and can affect setup if requests share a client-IP bucket. Local SMTP runs on 3102 with recipient-filtered mailbox on 3101. External Resend configuration is removed from the child server environment. SMS/social/e-sign providers remain unavailable; tests assert the applicable configuration error rather than pretending delivery succeeded. Password recovery uses the local SMTP sink. No migrations, reset or global development/reference seed command is part of this workflow.

Failure screenshots/traces and HTML/JSON reporters provide local evidence; authentication-focused security specs disable tracing where configured. Raw artifacts can contain credentials/request data and remain ignored. Markdown summaries omit raw errors, stacks, stdout, tokens, cookies and mailbox contents. Genuine failure assertions stay enabled; business logic changes require separate scope.

Detailed control source inventory is in [UI_FUNCTIONALITY_INVENTORY.md](UI_FUNCTIONALITY_INVENTORY.md).

Main c3aaaad: startup lead expiry is disabled only for PLAYWRIGHT_TEST_SERVER=1 because its global scope can mutate unrelated organizations. Vitest checks that guard and normal startup. Automatic expiry is inventoried but integration-blocked until a fully isolated database is provisioned; it is not covered by the browser tests. Missing contacts.expired_at and bill_items schema are environment blockers, never passing application behavior.
