# API endpoint inventory

Source inspection: 2026-11-04. **12 application GET endpoints**, plus one GET/POST Better Auth catch-all. The installed auth registry has **30 HTTP paths / 32 method-path pairs**; a separate pathless `setPassword` is server-only. Total concrete HTTP patterns: **42 paths / 44 explicit method-path pairs**, without double-counting the catch-all. Framework HEAD/OPTIONS and Server Actions are excluded. Registered auth endpoints may be disabled by configuration. Test references describe assertions, not passing results.

S: validation before authentication: missing/empty parameter → 400 JSON `{error:"<parameter> is required"}`; then 401 `{error:"Authentication is required"}` or 403 `{error:"Forbidden"}`. Nonempty parameters are not UUID-validated; DB failures become logged 500 JSON `{error:"Failed to fetch properties/floors/units"}`. No explicit selector cache headers.

Q: [property-floor-unit.queries.ts](../../src/features/properties/queries/property-floor-unit.queries.ts), [property-access.ts](../../src/lib/permissions/property-access.ts), [scope.ts](../../src/lib/permissions/scope.ts). Scope without owner columns supplies organization isolation; explicit grants restrict inventory.

F: [loadFileRecord](../../src/lib/http/file-route.ts) checks UUID before auth: malformed → 404 plain text Not found, even anonymously. AuthorizationError translates to 401 Authentication is required / 403 Forbidden. Missing/cross-organization records → 404 Not found. Disk failure logs and returns 404 Picture unavailable (images) / File unavailable (documents). Other loader exceptions are not caught by this helper.

I: stored MIME; private/no-store; nosniff; CSP `default-src 'none'; frame-ancestors 'self'; sandbox`. D: stored MIME or application/octet-stream fallback, private/no-store, nosniff, attachment disposition. Preview uses inline disposition and I security headers. Disposition includes safe ASCII fallback and RFC 5987 UTF-8 name. No explicit range handling. All 12 active routes are read-only business operations; failure logging is a side effect. [Storage](../../src/lib/storage/document-storage.ts) reads `.data/documents/<key>` and rejects root escapes; DB schemas are in [src/db/schema](../../src/db/schema).

Existing file tests: [public](../../tests/api/public.spec.ts) covers malformed/anonymous calls; [files](../../tests/api/files.spec.ts) has **42 cases**: success bytes/headers, nonexistent records, missing disk bytes, cross-organization denial for all eight routes; four missing image-key cases, two preview MIME cases and four grant-denial regressions. Denial assertions remain strict where current loaders omit grants.

## Authentication registry and configuration

AUTH-00: [catch-all](../../app/api/auth/[...all]/route.ts) exports GET/POST through toNextJsHandler. [Configuration](../../src/lib/auth/auth.ts): Better Auth minimal + Drizzle PostgreSQL + nextCookies. No social providers. Credentials enabled, public signup disabled; passwords inclusive 12–128; reset expiry 3600 seconds and reset revokes sessions; session expiry seven days, update age one day. Session creation requires active/nondeleted CRM user and active organization. Production requires secret/secure cookies. Trusted origins derive from environment plus localhost development patterns; IP source x-real-ip. Email-change/delete-user/verification-email delivery are not enabled. Reset mail callback is configured, asynchronous, and logs delivery failure.

All paths below have `/api/auth` prefix. Installed registry: [api/index.mjs](../../node_modules/better-auth/dist/api/index.mjs). It contains 30 HTTP paths, 32 method-paths and one pathless server-only function. `nextCookies` contributes hooks, not routes. This count was verified by introspecting endpoint descriptors without executing handlers, starting a server or opening DB connections.

Shared auth dependencies/effects: auth_users/accounts/sessions/verifications, password hashing, signed cookies, origin middleware, validation and framework JSON errors. Typical failures: 400 malformed/configuration, 401 credentials/session/token, 403 origin/account state, 404 disabled/absent provider, rate limits where enabled. GET session lookup can refresh cookies/session persistence. Authentication itself does not require a CRM module permission. Runtime CRM authorization additionally checks active user/organization.
